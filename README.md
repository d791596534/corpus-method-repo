# 历时中文语料库构建管线（方法、规则与代码）

1900—2026 年（英文报纸回溯至 1878）中文/英文历史文本语料库的**构建方法**。
包含版面判定规则、行级噪音判据、分句与拼回规则、按「年代 × 体裁」网格的配额抽样设计、
字符级质量验收口径，以及全流程管线代码。

> **关于语料本体**：默认**不发布语料正文**——源文本大多仍受著作权保护，部分还来自需登录访问的数据库。
> 判定按子库逐条做，依据是数据来源而不是数据规模：只有源本身进入公有领域的子库才随仓库发布正文
> （目前只有英文公文，美国联邦政府出版物，依 17 U.S.C. §105 不受著作权保护）。
> 该子库另附 5 个原生电子档源件样本，用于核对源件→成品的对应关系；图书馆数字化扫描影像不再分发。
> 其余子库只公开处理规则、判据与管线代码，样例仅收录已明确公版的条目。

## 目录

```
pipelines/            各子库的管线代码，按「单元 / 阶段号」组织，每个单元一份 README 说明阶段与判据
  en_official_reports/    01_extract → 02_clean_denoise → 03_integrate_2020s → 04_sotu_clean → 05_select_supplement
  <其余 7 个单元逐个补齐>
data/                 已公版子库的成品与源件样本，随附词数与校验和清单
  en_official_reports/    cleaned/ 247 个年代 txt + sources/ 5 个原生 PDF
```

方法、规则与验收口径都写在管线代码和每个单元的 README 里，不另设文档目录：
判据只有连着代码读才不会被误用，脱离具体脚本的通用规则文档在这个仓库里没有意义。

每个单元只放**实际生效的那一步的一件脚本**：同参数分批跑的合并为一个带年份参数的脚本，
中途被撤销的操作不进仓库。改写过的脚本都以处理过程中的中间产物做过逐字节回验。

仓库里的代码是从一批更细的实跑脚本整理出来的；整理映射表、逐步对账数字与踩坑记录属于开发过程记录，
不在发布范围内。

## 方法要点

**版面结构分类**。公报刊类只取正文段落，表格、标题、页眉页脚、页码一律计为噪音；小说类需保留
对话与行文标记，判据与公报刊完全相反。同一类规则**不跨子库复用**，逐库单独配置并留档理由。

**行级噪音判定**。设两道判据加一份豁免清单：先由形式特征（无句末终止符、零实义片段、符号占比）
提出候选，再按豁免条件（对话引号、外文夹注、该年代排版惯例）放行。所有删除动作先出**可人工
逐行审阅的清单**，确认后才执行，且执行前强制备份，可整批回滚。

**分句与断行**。以 pysbd 为基础，针对中文做了三处修正：逐段送模型而非整篇；引号必须落在分句
边界而非句中；零实义片段并回。断句结果与原文做**字符流拉平比对**，差异为零才算通过。

**抽样**。以句子为最小单位，配额单位是「年代 × 体裁」而非整库，步长按句数而非字数；不足时贪心
回填贴满配额，超出时宁低不超；验收看年代内文本的**覆盖率 ≥ 99%** 而非仅看总量达标。

**质量验收**。正确率 = 1 − 错字数 / 总字数（不计标点），错字由人工逐年逐库就地标红判定。
该口径只计替换与删除，**不等同于标准 CER**（CER 基于编辑距离且计入插入错误），二者不可混用。
抽检**每个年代都抽**，不以少数代表年份外推。

## 复现

```bash
export CORPUS_ROOT=/path/to/corpus        # 源 PDF 与中间产物目录；除英文公文外均不随仓库分发
export LLM_API_KEY=...                    # 代码不内置任何凭据
python -m pip install mineru==3.4.0 pysbd   # OCR 与分句依赖，见各单元 README
```

每一步写入新目录、源目录不动，可整步重跑；带 `--verify` 的脚本只读比对已有产物、不写文件。
仓库里发布的成品数据，其逐格词数、页数与 SHA-256 清单在 `data/<单元>/README.md`，
那里给了可直接粘贴运行的重算命令。

OCR 环节另需视觉模型批量接口，只有少数批次走它。管线支持断点续跑，中间产物与日志一律外移到
`_备份`，成品目录只保留交付文本与年代层级。
